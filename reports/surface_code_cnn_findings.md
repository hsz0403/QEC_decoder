# Surface-Code Code-Capacity CNN Decoder Findings

## Goal

This branch adds a new surface-code code-capacity dataset and CNN decoder pipeline on top of the
existing `bb-code-dataset-generator` branch. The BB-code generator code was not modified. The new
surface-code work lives in separate files under:

- `surface_code_capacity/`
- `scripts/generate_surface_code_iid.py`
- `scripts/visualize_surface_code_samples.py`
- `scripts/train_surface_code_cnn.py`
- `configs/surface_iid_d11_p005.yaml`
- `configs/train_surface_cnn_d11_h128.yaml`
- `configs/train_surface_cnn_d11_h512.yaml`

The initial target is a simple code-capacity learning task:

```text
sample iid binary errors e ~ Bernoulli(p)
syndrome = e @ H.T mod 2
logical_action = e @ L.T mod 2
learn syndrome -> logical_action
```

This intentionally removes measurement error. The error rate is `p = 0.05`, and the surface-code
distance is `d = 11`.

## Dataset Construction

Stim is used to construct a one-round rotated surface-code memory circuit with no measurement
noise. The circuit is converted into a detector error model only to extract the binary parity
check matrix `H` and logical-action matrix `L`. The actual dataset is then generated by iid
sampling binary error-mechanism vectors.

For the generated `d=11`, `p=0.05` dataset:

```text
train shots:          200,000
validation shots:     50,000
num detectors:        120
num error mechanisms: 111
num observables:      1
detector grid shape:  10 x 12
label positive rate:  0.23632
```

Files:

```text
runs/data/surface_iid_d11_p005_train.npz
runs/data/surface_iid_d11_p005_val.npz
```

Each `.npz` contains:

```text
events:           [shots, 120]
labels:           [shots, 1]
parity_check:     [120, 111]
logical_matrix:   [1, 111]
detector_coords:  detector coordinates from Stim
detector_grid:    integer CNN grid placement for each detector
logical_mask:     simple logical-support pooling mask
metadata_json:    generation metadata
```

## CNN Decoder Architecture

The implemented decoder follows the requested high-level structure:

```text
binary detection event
-> learned H-dimensional embedding
-> L convolutional residual bottleneck blocks
-> check-grid to data-grid convolution
-> pool over a logical-support mask
-> 2-layer MLP readout with hidden dimension 2H
```

The model is implemented in:

```text
surface_code_capacity/model.py
```

The primary configuration uses:

```text
hidden_dim H:       128
residual blocks L:  8
bottleneck ratio:   4
dropout:            0.05
loss:               BCEWithLogitsLoss
optimizer:          AdamW
batch size:         2048
epochs:             30 target
```

The H=512 experiment was also smoke-tested with:

```text
hidden_dim H:       512
residual blocks L:  4
epochs:             1
```

This was used as a capacity and runtime check, not a final tuned result.

## Interpretation

This new setup is much simpler than the previous `ml_bb_decoding` task. It removes measurement
noise and asks the model to learn a code-capacity map from detector syndrome to logical action.
This makes it a better first ML baseline for a machine-learning-first workflow.

The current H=128 model is only slightly above the all-zero baseline. H=512 is more promising,
with best validation LER `0.22180` versus the all-zero baseline `0.23632`, but training is not yet
stable because the final epoch regresses to `0.26014`. The pipeline is now in place: data
generation, visualization, model training, Slurm execution, checkpointing, and metrics all work
end to end.

Next steps:

1. Add an exact decoder baseline for the same generated dataset.
2. Improve the logical-support pooling mechanism using true data-qubit logical supports rather
   than the current simple detector-grid mask.
3. Sweep `p` and train on mixed error rates instead of a single `p=0.05`.
4. Tune optimization for H=512, especially learning rate, scheduler, early stopping, and class
   weighting, because the best checkpoint is much better than the final epoch.
5. Scale shot count toward larger datasets after the model beats stronger baselines clearly.
